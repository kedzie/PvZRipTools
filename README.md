# PvZRipTools

Disaster-recovery kit for the PvZ2-plant-ripping pipeline used to build
Pvz Complete Collection2's custom plants. The goal: given nothing but a
copy of the PvZ2 OBB files and this repo, you should be able to re-derive
everything - unpack the OBB, re-rip any plant's frames/sounds/seed packet,
and rebuild a Unity asset bundle - without having to re-discover any of
the tooling or the exact invocation details again.

## What you need in hand

1. **The PvZ2 OBB file(s)** (`main.*.com.ea.game.pvz2_*.obb`) - the actual
   game data. Nothing here works without these; they're not included or
   redistributed by this repo.
2. **This repo.**
3. **Unity 6000.0.60f1.** The project the scripts import into and build bundles from is in this repo
   as `unity/` - just the skeleton (two Editor scripts, `ProjectSettings`, `Packages`). Unity runs
   headless only; nothing is edited in the Editor. Everything it imports is PopCap/EA's ripped PvZ2
   art/audio, so `unity/.gitignore` is a whitelist that ignores all of it - it is regenerated by the
   pipeline below, never committed. (The old private project with its ripped-asset history,
   `ReverseEngineering/AssetBundle-UnityProject`, is just a local archive now.)

None of these are vendored here except `ww2ogg` (small, permissively
licensed, not PopCap content). Re-download the others fresh if starting
from scratch:

| PopStudio | github.com/PopGameTool/PopStudio | commit `e75c8ad4144dbcebd94557f4d807f3d74b00b91f` | Decoding `.PAM` (animation) and `.RTON` (resource database) files |

## The pipeline, end to end

1. **Unpack the OBB.** (The exact original unpack process isn't captured
   as a script - it was done once into a working folder referred to
   throughout these scripts as `pvz2_original_unpacked/`, containing
   `IMAGES/`, `ATLASES/`, `SOUNDBANKS/`, `PACKAGES/` etc.) Point the paths
   in `plants.json` at wherever you redo this.
2. **Decode `RESOURCES.RTON` to `RESOURCES.json`** via PopStudio's RTON
   decoder. The exact command-line invocation used originally wasn't
   captured in any script (it looks like it was run through PopStudio's
   interactive console menu, not a one-liner) - run `PopStudio.exe` with
   no arguments to get its menu and pick the RTON-decode option, pointed
   at `RESOURCES.RTON`. This is the one real gap in this recipe; if you
   redo this, capture the exact command and add it here.
3. **Rip a plant**: `python3 rip_plant.py <name-or-index>` (or `--all`).
   Reads the plant's entry from `plants.json` (already populated for all
   185 PvZ2 plants, not just the ones we've shipped - most future plants
   are "just run it," not "go find the PAM/atlas/resource IDs first").
   This decodes the plant's `.PAM` via PopStudio (`run_popstudio_decode_pam`,
   command code `180`), composites frames via `pam_compositor.py`
   (per-frame-cropped, centered on a shared reference so `pivot_x=0.5`
   always tracks correctly - see that file's own docstring), extracts and
   converts its `.BNK` sounds via `bnk_extract.py` + vendored `ww2ogg`,
   and crops its seed-packet icon via `crop_seedpacket` (note: the
   `UI_SEEDPACKETS` atlas has its R/B channels swapped at the source - see
   the comment on `crop_seedpacket` - already corrected for automatically).
   It also writes `sounds_manifest.json` (+ `projectile/` and `projectile_hit/` siblings) and rips
   any shared-bank sounds the plant's events use into `sounds/` - see "Sounds". Output lands in
   `D:/PvZ2RipTest/export_all/<PLANT>/`. **A plant with projectile art takes ~7 minutes** (PopStudio
   decode + compositing three PAMs) - run it in the background and poll, don't block on it. If a
   plant has projectile/impact art, add a `projectile` block to its `plants.json` entry first
   (alias + `attached_pam` + `impact_pam`; copy Apple Mortar's); `null` means "plant body only".
4. **Import into Unity.** In `unity/`, run (via
   `build_all_bundles.bat`, or the equivalent `-executeMethod` call
   directly): `PvZRip.Editor.PvZBundleBuilder.ImportAndBuildAllRipped`.
   This calls `PvZRipImporter.ImportPlantFull` for every plant folder
   under `export_all/` (or just the ones listed in
   `D:/PvZ2RipTest/build_only.txt`, one name per line, if you want to
   restrict it), builds Sprites/AnimationClips/an AnimatorController/a
   prefab per plant, tags each with its own asset bundle name, and builds
   every configured bundle in one pass.

   Bundles are built with `ChunkBasedCompression` (LZ4): the game loads them far faster at
   startup than Unity's default LZMA, which has to be decompressed whole (~26 s for 19 bundles,
   near zero with LZ4). To convert bundles that were built before this, put them in
   `D:/PvZ2RipTest/lz4_in` and run `-executeMethod PvZRip.Editor.PvZBundleBuilder.RecompressBundlesToLZ4`
   (output goes to `lz4_out`; content is unchanged, no re-import).

   **Important**: `ImportPlantFull` regenerates a plant's prefab and
   `AnimatorController` from scratch off the bulk-export defaults - if
   you've since hand-tuned a plant in the Editor (fixed transitions,
   added Animation Events for sounds, etc.), re-running this on that
   plant **wipes those changes**. For an already-imported, hand-tuned
   plant, add a small dedicated `Build<Plant>Bundle()` method to
   `PvZBundleBuilder.cs` that skips `ImportPlantFull` and just re-tags +
   rebuilds from the project's current state (see `BuildBambooSpartanBundle`
   for the pattern). Several plants also need their bulk-picked Animator
   defaults corrected in code after import - see
   `FixEndurianAnimatorController`, `FixCelerystalkerAnimatorController`,
   `FixTumbleweedAnimatorControllers` for the established pattern (a
   plant needs one of these whenever none of its clip labels is literally
   named "idle"/etc., or a clip that should loop doesn't have "idle",
   "water", or "loop" in its name).
5. **Bundles land in** `D:/PvZ2RipTest/bundles/` - copy the ones you need
   into the game's `Mods/CompleteCollection/` or `Mods/CoreLib/` folder.
   Note the bulk importer names them `pvz<plantname>bundle` directly (no
   "rip" prefix, no manual rename needed) as of the fix in this repo's
   history - if you're recovering from an older snapshot predating that
   fix, strip a leading "rip" from any bundle name it produces before
   copying it into place.

## Frame cropping and the anchor (applies to plants, projectiles, hit effects and extra effects alike)

Every exported frame follows the same rules (`pam_compositor.py`, `PamAsset.export_all`):

1. **One fixed anchor per animation set: bottom-middle of a reference line, the same for every frame of every clip.** It is what
   puts a plant centred in its square, and anything that jumps, slides, lunges or sinks does so *relative to that point* (it keeps
   its real motion). It is **not** each frame's own bottom edge: that was the old behaviour (`--anchor frame_bottom`, kept only for
   comparing), which re-aligned every frame to its own bottom, made static parts wobble (Chilly Pepper's ice slab) and flattened jumps.
   * **Plants (`--anchor standing`, the default): the lowest point of the standing clips**, i.e. every clip whose label contains
     `idle` = the plant's feet on the ground line. A clip that reaches lower (Bombegranate's explosion, Stallia's burst, a lunge)
     hangs below the feet; it must not lift the idle pose off the ground. A plant with no idle clip uses the first frame of its first clip.
   * **Effects, projectiles and hit effects (`--anchor lowest`): the lowest point of the whole animation set** (they have no
     standing pose).
   * Clips labelled `water*` (the plant standing in a ducky tube, which hangs below the feet) and `pf*` / `plantfood*` (Plant Food,
     never played in Replanted) are exported with the same anchor but never take part in finding the reference.
     (`plantfood*` clips are in fact not exported at all.)
2. **Vertical clip: as tight as possible, every frame.** The image is cut to the frame's own visible bbox, top and bottom
   (no transparent padding, no texture memory wasted). The fixed anchor is carried by the sprite **pivot**, not by padding:
   `pivot_y = (frame_bottom - reference) / frame_height`: 0 for a frame whose bottom is the reference, NEGATIVE (pivot below the
   image) for a frame whose bottom is higher, POSITIVE (pivot above its bottom edge) for a frame that reaches below the reference. Unity's custom sprite pivot accepts that.
3. **Horizontal clip: as tight as possible, symmetric around the anchor.** The anchor x is the horizontal centre of the first
   exported frame. Each frame's width is exactly 2 x its own furthest excursion (left or right) from that x, with the anchor kept at
   the exact centre (`pivot_x = 0.5`). So however far a frame reaches to one side, the image is that distance x 2 wide, and a
   frame with a small sway is a small image.
4. The importer applies each frame's `manifest.tsv` pivot as-is (`spriteAlignment = Custom`, 1 px = 1 unit). Nothing in the mod's C#
   adds a per-plant offset: everything is baked in here.

Consequence for game code: an effect / projectile placed "at a position" has its fixed anchor there (bottom-middle of its lowest
point), so work out the offset from the art (`manifest.json` has each frame's bbox) rather than assuming "pivot = bottom of the
sprite". Chilly Pepper's ice is the worked example (`ChillyPepper.cs`: slab centre is 168 px above the anchor).

## Sounds: frame-driven `PlaySound` events, derived from the data (not by ear)

**Rule (from the mod author): sounds are baked into the Unity clips as `PlaySound` Animation Events on
the exact keyframe, never played from code with fps maths** - the game has animation speed settings,
and an event on the clip's own keyframe follows them by construction. Code-driven timing
(`RegisterSoundPool`, `SetHitSfx`, timers) is only a fallback when an Animation Event cannot do it.

Where the information lives (all verified, Dusk Lobber / Celery / Tumbleweed / Fire Peashooter):

1. **The plant's `.pam.json`** - `main_sprite.frame[n].command` entries: `PlaySample` with the Wwise
   event name (`Play_Plant_DuskLobber_Attack`) on the frame it fires, plus `use_action` /
   `use_special` markers on the frame the plant actually acts (spawns the projectile, deals the hit).
   Those markers are also the real "launch frame" - useful when timing a projectile spawn.
2. **`GLOBAL_DATA.BNK` HIRC chunk** - event id = 32-bit **FNV-1** hash of the *lower-cased* name
   (`x = x*16777619 ^ byte`, start 2166136261) -> Event(type 4) -> Action(3, type `0x0403` = Play)
   -> Random/Switch Container(5/6) -> Sound(2) -> source WEM id. **A single event is usually several
   Play actions = several simultaneous LAYERS** (Dusk Lobber attack = plant sound set A + plant sound
   set B + a shared generic layer). Each layer picks ONE of its variants at random in the real game.
3. **`PLANT_<NAME>.BNK`** only holds media (DIDX/DATA, no HIRC); its WEM ids are the ogg names
   `bnk_extract.py` writes. A layer's sounds may live in another bank (`AUDIO_ALWAYS_LOADED.BNK` for
   generic whooshes/hits, `ICEAGE_AMB_WORLD_SFX.BNK` for Endurian's attack) - `plant_sounds.py`
   rips only the PICKED ones into the plant's `sounds/` folder.
4. **Impact (projectile hit) sounds are NOT in the PAM, and are CODE-driven, not animation events.**
   `PACKAGES/PROJECTILETYPES.json` -> the projectile's `ImpactSoundEvent` (e.g.
   `Play_Plant_DuskLobber_Impact`; `..._Impact_Plantfood` for the PF shot). `plant_sounds.py` resolves
   it into `projectile_hit/sounds_manifest.json` as `impact_sound_event` and prints the ready-made
   line `SetHitSfx(<BundleId>, "assets/plantrip/<plant>/sounds/<wem>.ogg")` - that is how the mod
   plays hit sounds (Tumbleweed, Bloomerang). The Unity bake deliberately does NOT touch
   `projectile_hit` clips (an earlier version did; it was removed - baking it AND `SetHitSfx` would
   double the sound).

`sounds_manifest.json` (per sub-object) = `{frame_rate, animations:[{label,start,end,frames,
events:[{frame, sample, layers:[{sounds:[wem..], banks:{wem:bank}, pick}]}], actions:[...]}],
unresolved:[...], nested_sprite_commands:N}`. `frame` is the offset INSIDE the label = the index of the
exported frame = the clip's keyframe index (frame *file names* are global PAM frame numbers, e.g.
`attack/frame_97.png`, but the manifest and the Unity keyframes use label-relative indices).

**Variant choice (`pick`)**: an Animation Event can reference only one clip, so the random
containers are flattened deterministically: occurrence N of an event (counted across the manifest in
timeline order) uses variant `N % len(variants)` of each layer - a looping hit doesn't repeat one wav and
re-running never reshuffles. True per-play randomness would need code (`PlaySoundEvent` + a registered
pool); the manifest keeps the full variant lists if you ever want that.

### Repeatable procedure

```bash
# 1. (re)generate manifests + shared sounds for any plants; no frames re-rip needed
python3 plant_sounds.py DUSKLOBBER CELERYSTALKER ...        # prints every event/layer + any UNRESOLVED
# 2a. NEW plant: full rip (writes the manifest itself), then import - ImportAndBuildAllRipped bakes automatically
python3 rip_plant.py DUSKLOBBER                              # ~7 min if it has projectile art
echo DUSKLOBBER > D:/PvZ2RipTest/build_only.txt              # (restore the previous content afterwards!)
cmd.exe /c D:\PvZ\ReverseEngineering\PvZRipTools\build_all_bundles.bat
# 2b. ALREADY-imported (hand-tuned) plants: bake only, never reimport
printf 'celerystalker\nbamboospartan\ntumbleweed\n' > D:/PvZ2RipTest/bake_sounds.txt
cmd.exe /c D:\PvZ\ReverseEngineering\PvZRipTools\bake_sounds.bat
# 3. verify in the Unity log:  grep "\[BakeSound\]" D:/PvZ2RipTest/unity_bake_sounds.log
```

`BakeSoundEventsForPlant` (in `PvZBundleBuilder.cs`, plant clips only) is idempotent: it first removes every
`PlaySound`/`PlaySoundEvent` event on the clips the manifest covers (so re-runs never stack duplicates
and hand-assigned events that disagree with the PAM are replaced - the log lists `removed [...] added
[...]` per clip), leaves every other event alone, and copies a missing shared-bank ogg from
`export_all/<NAME>/sounds` into the plant's Unity sounds folder and tags it with the plant's bundle.
Clips that don't exist in the project (e.g. `plantfood`, which the compositor skips on purpose) are
reported as "no such clip", not an error.

### Launch frame: an `ExecuteAttack` event (so the throw follows game speed too)

The PAM's `use_action` command (also `use_action1..N`, and `use_special`) marks the frame a plant actually
acts (releases its projectile / spawns its sun). The manifest keeps it as `animations[].actions[]`. Plants
listed in `LaunchEventPlants` (`PvZBundleBuilder.cs`, opt-in; value = which clip labels) get one
`ExecuteAttack` Animation Event on EVERY such frame of those clips (re-bakes replace them, never stack).
Currently: `dusklobber` (attack), `peanut` (attack*), `peapod` (attack*: `attack` + `attack 2`..`attack 5`, one event per head - stackable, see `PeapodBehaviorController`), `goldbloom` (attack, three pulses),
`primal_sunflower` (special). CoreLib forwards it: `AnimationScripts.ExecuteAttack()` ->
`CustomPlantBehaviorController.OnAnimationAttackEvent()` (virtual, no-op by default) - override that to spawn
the projectile / sun instead of using a timer. Needs a CoreLib build that has the hook. **Not yet verified in
game** (code and bake log only).

`launch_sound` (a plant's `plants.json` entry: `{"sample": "Play_Throw", "labels": [...]}`) adds the engine-played
`ProjectileLaunchSound` as a frame-driven event on each listed clip's EARLIEST `use_action*` marker (once per clip, not
once per marker - Peapod's `attack 2..5` have 2-5 markers 2-5 frames apart and identical stacked throws would be loud).
Each clip's random variant is picked per clip in rotation.

`OwnerDieClips` (same file) adds an `OwnerDie` event on a clip's second-to-last keyframe
(`AnimationScripts.OwnerDie` -> `Plant.Die`) - used by the instant plants (Gold Bloom, Chilly Pepper, Bombegranate,
Stallia) to remove themselves. The clip label may end in `*` (Bombegranate: `attack*` = attack, attack2, attack3).

Three more opt-in tables next to `LaunchEventPlants` (all in `PvZBundleBuilder.cs`), added for the 2026-11-21 instant/Mega
Gatling round:
* `ExtraLaunchCommands` - plant -> a PAM command name that also counts as a launch marker (Stallia's moment is a
  `freeze` command, not `use_action`).
* `ExtraLaunchOffsets` - plant -> frame offsets from the clip's EARLIEST marker, one `ExecuteAttack` each (the marker
  itself = offset 0). For a plant whose PAM marks ONE launch frame but fires a stream: Mega Gatling `{0,3,6,9,12}` =
  frames 16/19/22/25/28 of its 31-frame attack clip. The controller must know how many events there are.
* `ApplyPlantAnimatorFixes` cases `explodeonut` (damage tiers, like Primal Wall-nut) and `megagatling` (projectile loop).

A `plants.json` `projectile` block may carry its own `atlas_png` + `group_id` when the projectile art is not in the plant's
atlas (Mega Gatling's giant pea lives in `LEVELCOMMON_1536_00.PNG` / `LevelCommon_1536`); `rip_plant.py` passes them to the
compositor. `plant_sounds.py` also rips a projectile's **impact sound** pick when it lives in a shared bank (it used to
only look at animation-event layers, so a hit sound from `AUDIO_ALWAYS_LOADED` never reached `sounds/`).

### Clip frame rate

`ImportAndBuildAllRipped` imports every clip at 12 fps (`sampleRate`), which is what the older plants use.
PvZ2's own data is 30 fps (Peanut's two attack clips are 19 + 21 frames = 1.33 s = its 1.30-1.333 s shot
cooldown), so at 12 fps those clips run 2.5x long (Dusk Lobber's 45-frame attack = 3.75 s against a 3 s launch
rate). `SampleRateOverrides` (same file) lists plants imported at 30 fps instead; delete an entry to go back.
Event times are taken from the clip's own keyframes, so they stay in sync either way.

2026-11-22: the six original CC2 plants (Fire Peashooter, Bamboo Spartan, Endurian, Celery Stalker, Tumbleweed,
Iceweed) were re-imported at 30 fps too. Their per-plant fixes (`FixEndurianAnimatorController`, `FixCelery...`,
`FixIceweed...`, `FixTumbleweedAnimatorControllers`, Bamboo's Battle Trance exits) now run from
`ApplyPlantAnimatorFixes`, so `build_only.txt` + `ImportAndBuildAllRipped` reproduces them. Things that only work
with that import: `NoProjectileImport` (Iceweed's unused Plant Food art stays out of the bundle) and
`HandBakedSounds` (Tumbleweed's hand-placed rolling whooshes on the projectile, which the PAM has no events for).
`D:/PvZ2RipTest/build_outdir.txt` (optional, first line = output folder) redirects the build away from
`D:/PvZ2RipTest/bundles`, and while `build_only.txt` is present only the imported plants' bundles are built
(an unrestricted build rewrites every tagged bundle, Dusk Lobber's included). NOTE: the frames under
`export_all/<PLANT>/frames` of those older plants were stale (Aug fixed-width crops) - re-run `pam_compositor.py`
(it reproduces the shipped sprites byte for byte) before importing an old plant.

### Extra effects a plant spawns on its own (`effects` block, Chilly Pepper's lane ice)

A `plants.json` entry may carry `"effects": [{"name": "tile_ice", "pam": ".../CHILLYPEPPER_TILE_ICE.PAM",
"hold_frames": 30, "fade_frames": 15}]` (optional `atlas_png`/`group_id`, default = the plant's own atlas). `rip_plant.py`
composites each PAM like a projectile into `export_all/<PLANT>/effects/<name>/frames` and writes an `effect.json` next to it;
`python3 rip_plant.py --effects-only CHILLYPEPPER` re-rips just those (the plant's frames/sounds/seed packet and
`rip_results.json` stay untouched, so it is safe on an already-imported plant). On the Unity side
`PvZRipImporter.ImportPlantEffects` builds one prefab + AnimatorController per effect under
`models/default/effects/<name>/<name>.prefab` (30 fps per `SampleRateOverrides`, a play-once clip, default state = the clip,
nothing for code to start) and `TagPlantBundle` puts it into the plant's bundle, next to the plant prefab, seed packet and sounds
(bundle path `assets/plantrip/<plant>/models/default/effects/<name>/<name>.prefab`).

* `ImportAndBuildAllRipped` (build_only.txt + build_outdir.txt) does all of that as part of a normal plant import.
* `ImportEffectsAndBuildOnly` does ONLY the effects and then builds the plant's bundle from the project's current state - it
  never calls `ImportPlantFull`, so the plant prefab, clips (with their baked sound/ExecuteAttack/OwnerDie events), controller,
  sounds and seed packet are not regenerated. Wrapper: `D:/PvZ2RipTest/run_unity_effects.bat <logname>`.
* A PAM just stops on its last frame; how long the effect stays is the game's decision. `hold_frames`/`fade_frames` (0 = off)
  extend the clip frame-driven: the last sprite is held, then the SpriteRenderer alpha fades 1 -> 0 (an alpha curve in the clip,
  no code timer). The game destroys the instance after the clip length (`Object.Destroy(instance, seconds)`), like the hit effects.
* Chilly Pepper's `tile_ice` (PvZ2 `CHILLYPEPPER_TILE_ICE`, 20 frames, uses the plant's atlas): the effect has no reference
  anywhere in PvZ2's data (PLANTPROPERTIES/PLANTTYPES/RESOURCES only list the PAM and its atlas rects), so the stagger / lane
  / lifetime are the mod's choice - see `ChillyPepper.cs`.

### Effect options added 2026-11-23 (`labels`, `frame_rate`) and how to place an effect

* `"labels": ["animation"]` in an `effects` entry keeps only those clips of the effect PAM (PvZ2 effects usually carry 2-3
  random variants of the same burst - Snapdragon's fire, Primal Potato Mine's explosion, Aloe's heal; the unused ones are
  only bundle size). `rip_effects` deletes the other label folders and filters `manifest.json` / `manifest.tsv`.
* `effect.json` now also carries the effect PAM's own `frame_rate` (some are 24 fps, e.g. SNAPDRAGON_FIRE and the pea splats;
  most are 30). `PvZRipImporter.ImportPlantEffects` uses it for that effect's clip instead of the plant's rate. (Effects ripped
  before this have no `frame_rate` = plant rate; plant projectiles / hit effects still use the plant rate.)
* **Where does an effect go?** PvZ2 spawns an effect PAM at the plant's own PAM origin, and every exported frame is anchored in
  that same canvas (origin 800,800), so the effect belongs at `effect anchor - plant anchor` from the plant's anchor. Anchor x = the
  centre of the first exported frame, anchor y = `bbox_bottom - pivot_y * height` (all frames give the same value); both are in
  `manifest.json`. Example: Snapdragon fire (1048,1322) vs plant (1003,1061) = (+45, +261 down). The mod does the world-space
  part in `Plants/PlantEffectSpawner.cs` (anchor = the skin's `SpriteRendererSkin/anim` transform; one art pixel = its lossy scale).
  Sanity check by looking at the art: the placed effect should overlap the plant the way it does in the PvZ2 PAM.

### Opt-in launch/sound tables added 2026-11-23 (`PvZBundleBuilder.cs`)

* `ExtraLaunchSamples` - plant -> substring of a `PlaySample` name: an `ExecuteAttack` is baked on that sample's frame (Primal
  Potato Mine has no `use_action`; the blast is the `Attack_Explode` sample's frame).
* `ExtraLaunchFrames` - plant -> (clip -> clip-relative frame) picked from the art, for a clip with neither marker nor sample
  (Spring Bean `attack2`, frame 9: the stem is fully stretched).
* `HandBakedSounds` also holds Snapdragon's breath (the PAM has no `PlaySample` on its attack, but the soundbank has the event:
  id 952945927 -> 168056390/320177576/698354664) and Spring Bean's two sounds (3 unnamed events in the bank, assigned by
  duration - NOT by ear). Name->id: events with no name in any data file can still be found by reverse lookup: iterate the

to it). `ApplyPlantAnimatorFixes` runs right after it for plants that need more (Primal Wall-nut: the PAM's

`attack2` -> idle chains, per damage tier), so `build_only.txt` + `build_all_bundles.bat` reproduces them

## Pitfalls found the hard way (read before touching the pipeline)

* **Re-ripping Endurian wipes his hand-renamed idle tiers.** `rip_plant.py` rewrites `export_all/ENDURIAN/`
  with the PAM's raw labels, but the shipped bundle needs them renamed (see `FixEndurianAnimatorController`
  in `PvZBundleBuilder.cs`): `idle`->`armor`, `idle2`->`armor2`, `damage`->`idle`, `damage2`->`idle2`,
  `damage3`->`idle3`, in the frame folders AND in `frames/manifest.json` / `manifest.tsv`. Do it right after the
  re-rip and before the Unity import (`ExcludedPlantLabels` then drops `armor*`). Skipping it builds a bundle with
  `damage*` clips and no `idle3`, twice the size. After any bulk rebuild, diff each new bundle's AnimationClip
  names and sprite count against the shipped one (UnityPy); only intended changes should show.

* **Never commit anything under `unity/Assets/` except `Editor/`.** `unity/.gitignore` is a whitelist for
  that reason (the imported assets are ripped PopCap/EA art and audio); don't `git add -f` around it.
  Before pushing, `git ls-files unity` should list only the Editor scripts, `ProjectSettings`, `Packages`.
* **Seed packets: always R/B-swap `UI_SEEDPACKETS` tiles - for every plant, Dusk Lobber included**
  (a green body with purple thorns is correct, confirmed by the mod author). An automatic "match the
  packet to the body frames" heuristic was tried and was WRONG; don't reintroduce it.
* **A PAM can contain TWO complete art sets** drawn on top of each other (Dusk Lobber: every part as
  `<name>` = normal green and `<name>_2` = the `_dark` blue variant, both appended on frame 0; probably
  a Plant Food / dark-state skin the game toggles at runtime). The flat export then shows the top set
  (blue). Tell: a plant whose frames don't match its packet, or `image` names ending `_2` in
  `.pam.json`. Fix: `"skip_image_suffix": "_2"` in the plant's `plants.json` entry (passed to
  `pam_compositor.py` as `PAM_SKIP_IMAGE_SUFFIX`). The dark set is not exported (could be a future
  alternate skin).
* `PlantFood` and a few other labels are skipped by the compositor (`skip_labels_containing`), so those
  clips never exist in Unity - their sound events are reported and not baked.
* Unity batch runs: ~1-3 min; Unity must not be open on the project; the log
  (`unity_*.log`) contains `Licensing ... 404` lines - noise, ignore. (The old project also printed ~186
  `Could not load file or assembly 'MelonLoader'` errors from plugin DLLs; `unity/` has no plugins.) Look for `[BakeSound]`,
  `[PvZRipImporter]`, `[PvZBundleBuilder]` and `error CS`. `BuildAssetBundles` rebuilds EVERY tagged
  bundle into `D:/PvZ2RipTest/bundles` (staging only - the game's `Mods/` folder is never touched by
  these scripts; copy bundles by hand/with the release process).
* `build_only.txt` restricts `ImportAndBuildAllRipped` to the listed plants and **ImportPlantFull
  wipes hand tuning** of whatever it imports - always back up first (`cp --parents` the plant's
  `*.anim`/`ac.controller`) and restore `build_only.txt` afterwards.
* `rip_plant.py` rewrites `rip_results.json` (tracked) - `git checkout rip_results.json` after one-off
  runs unless you mean to update it.
* Several `rip_plant.py` processes in parallel are fine (each writes its own `rip_work/<P>` and `export_all/<P>`) but every one
  overwrites `rip_results.json` with only its own result - copy the file first and put it back after a parallel batch.
* A `PlaySample` event whose layers come out empty (`pick` missing; Aloe `Attack_Start`/`Charged`, Primal Potato Mine
  `Attack_Start`) is a silent event in PvZ2's own data, not a bug; a layer whose WEM id is in no bank (`banks: null`; Primal Potato
  Mine `Emerge` 33767102 and one `Attack_Explode` layer 78473496) has no media in this OBB - the bake logs "missing ...ogg" and
  skips it. The other layers of the same event still play.
